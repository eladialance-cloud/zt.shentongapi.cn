# 深瞳 · 多维表格字段设计规范

> 版本：v1.0
> 适用：深瞳 AI 数字员工（三省六部 + 太子 + 钦天监 + 早朝简报官）在各数据表/看板中的字段结构。
> 约定：字段命名统一、类型先定义、必填项决定写入前校验；数据优先可采集、查询高效；凡引用外部内容均已完成去品牌与 ≥30% 改写。

---

## 字段类型说明

| 类型标识 | 多维表格类型 | 说明 |
|---------|-------------|------|
| TEXT | 文本 | 单行/多行文本输入 |
| NUM | 数字 | 整数或小数 |
| DATE | 日期 | 日期时间选择 |
| SELECT | 单选 | 从预设选项中选择一项 |
| MULTI | 多选 | 从预设选项中选择多项 |
| CHECK | 复选框 | 是/否布尔值 |
| USER | 人员 | @成员 / @Agent |
| LINK | 超链接 | URL 链接 |
| FILE | 附件 | 文件/图片上传 |
| RATING | 评分 | 1-5 星评分 |
| FORMULA | 公式 | 自动计算字段 |
| LOOKUP | 查找引用 | 引用其他表字段 |
| RELATE | 关联 | 关联其他表记录 |

---

## 通用字段约定

- **主键**：每张表必须有唯一编号字段（如 `TA-YYYYMMDD-NNN`），保证可回溯。
- **必填**：写入前校验，缺失必填字段时禁止落库并上报阻塞。
- **状态**：统一用 `SELECT` 单选，枚举值集中维护，避免自由文本造成口径漂移。
- **时间**：统一 `DATE`，按 Asia/Shanghai 记录；自动生成字段用 `FORMULA`。
- **人员/Agent**：统一 `USER`，关联到工单/看板的执行主体。
- **口径文档**：字段含义变更须同步更新本文档，礼部（数据情报）负责审计字段口径一致性。

| official | TEXT | 是 | 当前责任官署 | 工部 |
| org | TEXT | 是 | 所属部门 | 六部/三省/太子/钦天监 |

| now | TEXT | 否 | 当前进展 | 客户名单导入中 |
| eta | DATE | 否 | 期望完成时间 | 2026-09-09 18:00 |
| block | TEXT | 否 | 阻塞原因 | 缺少前置素材 |
| output | TEXT | 否 | 产物描述/路径 | 短视频成品+脚本 |
