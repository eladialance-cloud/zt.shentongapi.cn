## 一、链路怎么走（三层）

```
蓝本 SOUL.md                     official-tables.json                 飞书
{{FEISHU_DOC:表名}}   ──渲染──▶  { envKey, name, url }   ──写入──▶  多维表格 / 云文档
```

1. **蓝本层**：`resources/edict/profiles/<官署>.md` 里写 `{{FEISHU_DOC:<表名>}}`，只写占位符，**不写链接**（禁止编造）。
2. **映射层**：一键建表把「表名 →table_id→ 链接」落盘到 `<userData>/edict-data/feishu-bitable.json`，并按 `TABLE_ENV_KEY` / `ENV_KEY_OWNER` 回填到 `<userData>/edict-data/official-tables.json`。
3. **渲染层**：`official-detail.renderSoulWithTables()` 把占位符换成真实链接，写入 `<userData>/hermes-home/profiles/<官署>/SOUL.md`。没回填时保留占位符（不伪造链接）。

代码单一真源：`desktop/electron/main/official-detail.ts`（表清单）、`feishu-bitable.ts`（envKey/归属）、`strategic-doc.ts`（战略方向文档）。

## 五、谁在什么时机写（提前输入 vs 运行时填入）

| 时机 | 谁 | 写什么 |
|------|----|--------|
| 一键组队（建表阶段） | 客户端 | 建 1 个多维表格应用 + 23 张表 + 填 `official-tables.json` |
| 一键组队（建档阶段） | 客户端 | 建《战略方向文档》云文档 + 写初始提纲 + 回填中书省 |

| 每轮官署执行 | 编排器 | 官署产出 → 本地 `official_outputs`；收口时 → 归档索引表 |
| 战略迭代 | 中书省 | 战略方向文档正文 + 中书省·战略表版本记录 |
| 业务流定时任务 | flows 引擎 | 按第四节的落点表写入 |

**需要人工提前输入的**：飞书 App ID / App Secret（平台设置）、战略方向文档正文（首次建档后由用户或中书省补全）、关键词种子（可选，随包分发）。

**由各官署运行时填入的**：各官署专属表的业务记录、共享表的读对齐信息、任务主表的状态流转。

## 六、常见排查

| 现象 | 原因 | 处理 |
|------|------|------|
| SOUL 里还是 `{{FEISHU_DOC:xxx}}` | 表未建 / 未回填链接 | 跑「一键组队 → 一键建表」，再看 `official-tables.json` |
| 某张表没建出来 | 飞书拒绝整表（字段类型需要 property） | 见 `feishu-bitable.json` 的 `failed` / `droppedFields` |
| 新增列没生效 | 旧表缺列 | 重跑一键建表：复用已有表时会自动补列（`ensureFields`） |
| 写入被整条拒绝 | 写了 SELECT/DATE/USER/LINK 列 | 编排器只写文本列；flows 侧请核对列类型 |
