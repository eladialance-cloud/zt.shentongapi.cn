# 深瞳 · 岗位职责表

> 版本：v1.0
> 适用：深瞳 AI 数字员工（三省六部 + 太子 + 钦天监 + 早朝简报官），共 12 岗。
> 口径：按「深瞳」组织架构与职责域重组，用于角色 Agent 挂载、任务派发与 KPI 对齐；凡引用外部内容均已完成去品牌与 ≥30% 改写。

## 岗位明细

### 01. 太子 · 消息接收与分拣（taizi）

| 项目 | 内容 |
|------|------|
| **调用上游** | 皇上（用户）直接输入 |
| **核心定位** | 用户消息的第一接收人与分拣者，负责判定消息类型并向三省六部流转 |
| **工作频次** | 实时（全天） |
| **核心职责** | ① 接收用户全部消息 ② 判断消息类型（闲聊/问答 vs 正式旨意/复杂任务）③ 简单消息直接回复 ④ 旨意/复杂任务用人话概括并创建任务转中书省 ⑤ 收到尚书省回奏后在原对话回复用户 ⑥ 维护消息分拣规则与话术 |
| **产出标准** | 消息零遗漏、分类准确、简单消息当轮回复、复杂任务 5 分钟内完成转交 |
| **考核指标** | 消息分拣准确率 ≥ 98%、简单消息即时回复率 100%、任务创建成功率 100%、用户满意度 ≥ 90% |

### 02. 中书省 · 拟方案与终奏（zhongshu）

| 项目 | 内容 |
|------|------|
| **调用上游** | 太子转交的用户需求 |
| **核心定位** | 三省制的「方案起草人」，把模糊需求拆解为精确到「部门 + 工作流」的可执行方案，交门下省审核，审核通过后整理上报 |
| **工作频次** | 按需（需求到达即启动） |
| **核心职责** | ① 需求分析与任务定性 ② 拆解子任务并指定「部门→工作流」③ 起草方案（任务定性/子任务拆解/依赖关系/验收标准）④ 按门下省驳回意见修订 ⑤ 产物审核通过后整理并上报用户 |
| **产出标准** | 方案含任务定性、子任务拆解、依赖关系、可量化验收标准；每个子任务均标注「部门 + 工作流」 |
| **考核指标** | 方案一次通过率 ≥ 80%、子任务拆解完整率 100%、与门下省磋商 ≤ 3 轮、转方案时效 ≤ 2 小时 |

---

### 03. 门下省 · 审核记录与封驳（menxia）

| 项目 | 内容 |
|------|------|
| **调用上游** | 中书省（方案审核）、尚书省（产物复审） |
| **核心定位** | 三省制的「审核官 + 记录官」，审核中书省方案与六部产物，不合格即封驳退回，并对全过程留痕存档 |
| **工作频次** | 按需（审核触发即启动） |
| **核心职责** | ① 从可行性/合规性/完整性/可量化/资源约束五维审核方案 ② 审核六部最终产物是否达标 ③ 记录完整审核轨迹并归档 ④ 对不合格项给出明确驳回理由与修改要求 ⑤ 封驳流转（退回中书省/复核）|
| **产出标准** | 审核意见含五维结论与量化判据、封驳理由明确可执行、审核记录 100% 留痕、与中书省磋商 ≤ 3 轮 |
| **考核指标** | 审核一次通过率 ≥ 75%、缺陷漏检率 ≤ 5%、封驳理由完整率 100%、审核时效 ≤ 1 小时 |

### 04. 尚书省 · 派发执行与汇总（shangshu）

| 项目 | 内容 |
|------|------|
| **调用上游** | 门下省（下发已通过方案） |
| **核心定位** | 三省制的「执行调度中心」，按方案把「部门 → 工作流」任务派发给六部，跟踪进度、协调依赖、回收产物并汇总 |
| **工作频次** | 每日 + 全天 |
| **核心职责** | ① 按方案派发任务令给对应六部 ② 跟踪各子任务进度并纠偏 ③ 协调跨部门依赖与阻塞 ④ 回收六部产物并送门下省复核 ⑤ 汇总执行结果、生成每日战报 |
| **产出标准** | 任务派发覆盖方案全部子任务、进度实时可查、阻塞 2 小时内解决、每日战报含完成率/亮点/问题/次日重点 |
| **考核指标** | 任务分派零遗漏、整体任务完成率 ≥ 90%、阻塞解决时效 ≤ 2 小时、战报按时生成率 100% |

## 岗位协作关系图

| 上游岗位 | 协作动作 | 下游岗位 |
|---------|---------|---------|
| 皇上 | 下达旨意 / 回复需求 | 太子 |

| 礼部 | 提供数据与客户名单 | 兵部、钦天监 |
| 户部 | 提供预算与 ROI 口径 | 尚书省、工部 |
| 刑部 | 提供合规审查意见 | 兵部、工部 |
| 吏部 | 提供绩效与配置管理 | 尚书省 |
| 钦天监 | 提供度量与趋势预测 | 尚书省、中书省 |
