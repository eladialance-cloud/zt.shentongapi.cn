## 二、手工验收（真机 + 真实飞书账号，按顺序做）

### A. 前置：飞书自建应用（首次实施方做一次）

1. 飞书开放平台建自建应用 → 开权限：`bitable:app`（多维表格读写）、`docx:document`（云文档读写）、`drive:drive`（云空间）。
2. 客户端「设置 → 飞书平台」填 App ID / App Secret → 点「测试连接」。
   - 期望：提示连接成功，且不再显示「未配置」。
   - 失败判定：401/权限不足 ⇒ 回飞书后台补权限并重新发布应用版本。

### B. 一键建表（幂等 + 补表补列）

3. 「设置 → 一键组队」选**标准版**→ 执行，看步骤条 `cleanup → bitable → agent → soul → strategic → seed → cron` 全部完成。
4. 重复点第二次「一键组队」（同一套餐）。
   - 期望：**不再新建第二份多维表格**（复用已有 app），日志出现「复用已有工作台」；无重复表。
5. 打开 `userData/edict-data/feishu-bitable.json`（或飞书里直接看）。
   - 期望：**23 张表**全部建出；`failed` 为空或被拒字段列表（`droppedFields`）仅剩 RELATE/FORMULA/LOOKUP 类降级项。
   - 重点确认：`军机处·任务主表`、`归档索引表`、`中书省·战略表`、`兵部·客户档案表` 都在，且链接 `?table=tbl...` 可打开。
6. 老装机升级路径（重要）：用 2.1.4 已建过表的账号升级到 2.1.5，再点一次「一键创建」。
   - 期望：已有表**不重建**，日志形如「复用已有表：X（补 N 个字段）」——即老表会被补上本次新增的列。
   - 失败判定：老表缺列且日志无「补 N 个字段」⇒ 记 bug。

### C. 战略方向文档（建档 + 牵头方 + 版本留痕）

7. 「设置 → 飞书平台」看「战略方向文档」卡片 → 点击。
   - 期望：能打开云文档，正文有初始提纲（愿景/人群/产品/竞品/飞轮等 6 段起）。
8. 看「中书省·战略表」→ 期望有 1 条 `V1.0`，`reason` 为「一键组队首次建档」，`summary` 非空。
   - 失败判定：无记录 ⇒ 战略表未建或建档回调未触发。
9. 复跑「一键组队」时若战略文档已存在。
   - 期望：**复用**同一文档，不新建、不覆盖用户已写正文，也不重复写 V1.0 记录。

### D. SOUL 占位符与共享表链接

10. 「任务中心 → 三省六部 → 任一官署 → 飞书表 tab」。
    - 期望：能看到该官署**多张**专属表（兵部 5 / 工部 3 / 礼部 3 / 中书省 3，其余 1–2 张）+ 共享表；「归属」列标注 `专属` / `共享`，共享表显示`主写：XX`，非主写官署的权限列显示「只读」。
11. 同一 tab 上看「占位符预览」。
    - 期望：`待回填 0 处`；若有橙色「查看待回填」⇒ 点开看是哪个表名缺链接。
12. 打开该官署的 `SOUL.md`（或页面上查看渲染结果）。
    - 期望：`{{FEISHU_DOC:...}}` 已全部替换成真实飞书链接；中书省一行是《战略方向文档》且**可点开**。
13. 共享表借用：只让主写官署回填链接（例如户部填财务收支表），看工部的同一张表。
    - 期望：工部页面也能拿到同一条链接，权限为「只读」。

### E. 战略文档运行时读取（本次最高价值项）

14. 在飞书里把《战略方向文档》的「战略目标/重点人群」改一句话（比如把重点人群加上「本地生活商家」）。
15. 等 5 分钟（读取有 5 分钟 TTL 缓存），或重启客户端。
16. 新建一道旨意（对话里下旨，走完需求确认）。
    - 期望：编排日志里中书省节点的方案**体现新改的这句话**；尚书省派发节点用摘要口径。
    - 失败判定：方案里完全没有新内容 ⇒ 看日志是否走缓存/读取失败；prompt 里出现「战略方向：未接入」说明链接或权限有问题。
17. 断网（或把飞书凭证临时改错）再下旨。
    - 期望：编排**不中断**，prompt 里注明「战略方向：未接入（…）」，产物照常跑完。

### F. 官署产出落飞书（写入通道）

18. 完成一道旨意到收口（Done）。
    - 期望：`军机处·任务主表` 出现该任务一行（标题/状态/官署），`归档索引表` 出现收口记录。
    - 失败判定：两条都无记录 ⇒ 看客户端日志 `[feishu-board]`；「只写文本列」是设计约束，SELECT/DATE 列不会被写。
19. 把飞书凭证临时改错再跑一道。
    - 期望：编排仍能完成，只 `console.warn`，不报错、不阻塞。

### G. 定时任务节拍（44 条）

20. 「任务中心 → 定时任务」。
    - 期望：只为**所选套餐内**的官署建了任务；标准版能看到 08:00 尚书省作战地图、08:30 工部海报、08:45 礼部关键词、09:30 兵部客户跟进、20:00 尚书省战报等。
    - 参考总量（按 `DEFAULT_CRONS` 实测）：轻量版 **27 条** / 标准版 **37 条** / 旗舰版 **44 条**。
21. 对外动作确认执行方式：兵部·早间私域推送、兵部·客户跟进、工部·每日海报、工部·公众号文章、礼部·爆款采集、工部·文案二创 = **业务流（flow）**；其余为官署执行（llm）。
    - 期望：列表里能看到执行方式/业务流 id；llm 任务不带 flowId。
22. 等到至少一个整点（如 06:00 早朝简报 或 07:00 中书省方案规划）看是否触发。
    - 期望：任务中心出现对应团队任务/执行记录；关掉主窗口也照跑（常驻引擎）。
    - 失败判定：不触发 ⇒ 检查登录态（定时任务依赖登录拉起守护进程）。

### H. flows 落点（可选，仅当决定切 `storage_backend=feishu`）

23. 未切换时：flows 保持 `local`，映射文件也应已写好。
    - 检查 `userData/service-registry/flows/config.json`：`storage_feishu.app_token` 有值，`storage_feishu.tables` 的**键是 collection**（如 `content_assets`），不是 `FEISHU_CONTENT_TABLE`。
    - 这是本次修掉的缺陷：键写错会导致「有映射却找不到表」。
24. 若切换：改 `config.json` 的 `storage_backend=feishu` → 重启 flows 服务 → 跑一次 `traffic-collect-hot-videos`。
    - 期望：对应飞书表出现记录；若返回 `STORAGE_BACKEND_UNAVAILABLE` ⇒ 检查 app_token/table id/collection 三个键。

### I. 回归（必须做）

25. 未建官署的新账号：不点一键组队时，任务中心 5 个 tab 正常空态，不报错。
26. 删官署：「设置 → 一键组队 → 删除某官署」→ 期望 profile 目录与该官署定时任务一起被清掉，**不误删同名任务**。
27. 关掉主窗口 10 分钟再打开：期望没有重复写表、没有重复任务。

## 三、发布操作步骤（严格按 `deploy/DESKTOP-RELEASE-SOP.md`，该文件是唯一权威流程）

```bash
# 1) 上传（本机执行；CI 产物只有 exe + latest.yml，没有 zip）
#    scp ShenTongAI-Setup-2.1.5-x64.exe latest.yml ubuntu@129.204.227.200:/tmp/

# 2) 服务器换包（/opt/shentong/updates 是 nginx 只读挂载源）
cd /opt/shentong/updates
sudo cp latest.yml latest.yml.bak.$(date +%Y%m%d%H%M%S) 2>/dev/null || true
sudo rm -f ShenTongAI-Setup-*.exe ShenTongAI-Setup-*.exe.zip ShenTongAI-*.exe.zip
sudo mv /tmp/ShenTongAI-Setup-2.1.5-x64.exe /tmp/latest.yml /opt/shentong/updates/
# ⚠️ 必须生成带 Setup 前缀的 zip（官网/下载页依赖该文件名，漏了会 404）
sudo zip -j ShenTongAI-Setup-2.1.5-x64.exe.zip ShenTongAI-Setup-2.1.5-x64.exe
sudo chown -R www-data:www-data /opt/shentong/updates/

# 3) 验证
curl -s https://zt.shentongapi.cn/desktop/latest.yml | head -3                            # 期望 version: 2.1.5
curl -sI https://zt.shentongapi.cn/desktop/ShenTongAI-Setup-2.1.5-x64.exe.zip | head -3   # 期望 HTTP 200

# 4) 官网版本登记（最容易漏：官网读数据库 client_versions，不读服务器文件）
#    生产库是 shentong（不是 ai_agent）；platform 必须是 win
$sql | ssh ubuntu@129.204.227.200 'sudo docker exec -i shentong-mysql mysql --default-character-set=utf8mb4 -uroot shentong'
#    等价手工 SQL 见 deploy/publish-2.1.5.sql

# 5) 唯一判据：接口返回的版本号
curl -s "https://zt.shentongapi.cn/api/version/check?platform=win&currentVersion=0.0.0"
```

## 四、回滚

```bash
# 只回滚安装包（客户端自动更新立即回到上一版）
cd /opt/shentong/updates
sudo cp latest.yml.bak.<刚才备份的时间戳> latest.yml
# 若是整包回滚：把上一版本 exe/zip 重新放回该目录并恢复对应 latest.yml
curl -s https://zt.shentongapi.cn/desktop/latest.yml | head -3   # 确认 version 已回退

# 回滚发布登记：把 2.1.5 置为不激活、恢复上一版激活
sudo docker exec -i shentong-mysql mysql --default-character-set=utf8mb4 -uroot shentong -e \
  "UPDATE client_versions SET is_active=0 WHERE platform='win' AND version='2.1.5'; \
   UPDATE client_versions SET is_active=1 WHERE platform='win' AND version='2.1.4';"
```

**数据侧不需要回滚**：本版对飞书只做「建表 / 补列 / 追加记录」，不删不覆盖用户数据；如需停写飞书，清空「设置 → 飞书平台」凭证即可（编排会自动降级为不写）。
