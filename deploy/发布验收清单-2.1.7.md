### 2.1 为什么必须先做

桌面端 2.1.7 的素材库页/素材与混剪页会发送 `library` / `kind` 查询参数；线上校验管道对未知参数返回 400，
旧后端会让素材列表整片报错。

### 2.2 部署前线上状态（实测）

- `/opt/shentong/backend` 源码停在 `d5f0cd7d24`（9/3）+ 今早手工补的 scheduled-tasks 补丁；`dist` 由该源码构建。
- 缺失接口：两阶段剪辑（`render-edit`）、IP 档案（`ip-archives`）、素材两库（`library`/`kind`）；混剪建议（`mix-suggest`）已存在。
- 结论：选「后端整体对齐分支」（用户 2026-09-14 决策 B），避免再留一处生产/仓库分叉。

### 2.3 执行步骤（可复现）

### 2.4 部署事故与修复（重要，已闭环）

- **现象**：首次重启后服务崩溃重启循环，日志 `Migration "DropAgentOpenclawAgentId1788451200012" failed, error: Can't DROP 'openclaw_agent_id'`。
- **根因**：迁移的存在性守卫写成 `if (!rows[0]?.c) return;`，而 **mysql2 把 `COUNT(*)` 以字符串返回**，
  `'0'` 是真值 ⇒「列不存在」被误判成「列存在」⇒ 执行了必然失败的 `ALTER TABLE eco_agents DROP COLUMN`。
  同文件模式的 `1788451200014` 有同样缺陷（`1788451200010` 用的是 `Number(row?.c || 0) > 0`，因此没问题）。
- **修复**：两处守卫改为显式数字判断（commit `903c5e7f`），重新编译后 pending 迁移清零、服务正常启动。
- **教训**：迁移里的 `COUNT(*)` 一律显式 `Number()` 转换；不要依赖驱动返回类型。

### 2.7 迁移通道门禁闭环（2.1.7 补录）

- **现象**：CI `migration:gate` 在 `126dcb0d`(#255) / `0d935684`(#256) 两个提交上失败——`db-migration.ts` 新增了
  素材两库 + 形象合一的 `ALTER TABLE` / `CREATE TABLE`，但变更范围内没有新增 TypeORM 迁移类。
- **为何 #257 之后又绿了**：`903c5e7f` 修改了既有迁移文件（`0012`/`0014`），门禁按「路径是否出现」判定，于是「借道通过」——
  属于过得不明不白，不是真正合规；一旦后续再有 legacy 结构变更就会复现。
- **修复**：补 `backend/src/migrations/1788451200015-SyncMediaAssetTwoLibraries.ts`，把本次 DDL 正式登记进 TypeORM 通道，
  并把它作为唯一真源之外的「可回溯记录」：幂等（先查 `information_schema` 再执行）、`down()` 可逆、`COUNT(*)` 一律 `Number()`。
  生产库/历史库已由启动迁移执行过同样的 DDL，故本迁移在线上是 no-op（只登记不改变结构）。

## 四、手工验收（真机，按顺序做）

### A. 素材两库

1. 「素材库」页顶部两个一级 Tab：**用户输入库 / 生成素材库**（各带说明文案）。
   - 期望：输入库二级类别含 图片/视频/音频/声音/形象/IP 档案/文档；生成库含 文案/图片/视频/音频。
   - 失败判定：切到生成库还能看到「声音/形象」类别 ⇒ Tab 映射未生效。
2. 在输入库上传一张图片 → 列表出现该条，带类别与库标签。
3. 口播工坊跑一条任务到出片 → 到生成库看任务产物是否自动入库（含来源标记）。
   - 期望：官署（三省六部）任务、媒体生成任务、口播工坊产物都进生成库，不用手动登记。
4. 语义检索框输入关键词 → 结果只来自**当前所在库**。
5. 输入库「形象」类别：能看到「我的形象」里建过的数字人（两库改造后形象并入素材库）。
   - 失败判定：形象类别为空但「我的形象」里有数据 ⇒ 后端形象合并未生效（检查 2.5 的 `media_asset_avatar`）。

### B. 画中画联动（本次主功能）

6. 「口播工坊 → 素材与混剪」→ 选一个任务 → 点「生成建议」。
   - 期望：出现若干张建议卡（关键词 + 字幕 + 匹配素材 + 位置/大小）。
   - 依赖：素材需先向量化（状态「已就绪」）才能被匹配。
7. 对某条建议点「加入画中画」。
   - 期望：提示「已加入画中画待用队列（N 条）」，页头出现「画中画待用 N 条」按钮。
   - 反例：该建议无匹配素材时应提示无法加入，而不是静默成功。
8. 点「画中画待用 N 条」（或从「口播工坊 → 工作台 → 剪辑步骤 → 添加画中画」）打开画中画弹窗。
   - 期望：弹窗顶部出现「来自「素材与混剪」的待用建议（N）」，每条有 使用 / 删除，另有「全部加入 / 清空」。
9. 点「使用」一条 → 待用队列少一条，画中画列表多一条；点「全部加入」→ 最多补到 4 个，超出部分保留在队列并提示。
10. 提交任务出片 → 成片按设置的位置/大小/时间段叠加画中画。
    - 期望：≤4 个；位置（左上/右上/左下/右下/居中）与缩放比例与设置一致。

### C. 口播工坊素材页收敛

11. 「口播工坊 → 素材与混剪」页应**不再有**上传/登记 URL/向量化/归档按钮；右上角是「去素材库维护原料」。
    - 期望：跳转到素材库页；列表是只读输入库素材。
12. 选任务后「一键导入该任务产物到素材库」→ 提示导入数（幂等：重复点提示已全部导入过）。

### D. 一键组队定时任务（本次顺带修复）

13. 「设置 → 一键组队」选同一套餐**连点两次**。
    - 期望：第二次提示 新建 0 条、跳过 N 条；**不再**把定时任务翻倍（历史 44→88 的问题）。
14. 看提示里的「修正排期 / 清理历史重复」计数：老账号应能看到清理重复行。
15. 「任务中心 → 定时任务」核对总量与套餐一致（轻量 27 / 标准 37 / 旗舰 44），周任务显示为每周而非每天。

### E. 回归（必须做）

16. 发布中心「关联素材」：默认读生成库，可切到输入库选封面；发布一条不报错。
17. 老装机（2.1.6 升 2.1.7）：素材库页、素材与混剪页、画中画弹窗均不报 400/500。
18. 关主窗口 10 分钟再开：无重复入库、无重复定时任务。
