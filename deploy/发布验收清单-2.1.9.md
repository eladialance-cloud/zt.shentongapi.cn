# 2.1.9 发布验收清单（生成素材库「来源」筛选 · 口播成片）

> 承接 2.1.8：上一版把素材库页收敛为「单层 · 两库」，删掉了重复的「合成视频」入口。
> 本版把「成片」做成**生成库里的一个筛选项**（不再加一层 Tab）——即当时给出的推荐方案。
> 本版**含后端改动**，部署顺序：**后端先行**，再发桌面端。

## 一、为什么用「来源」筛选，而不是再加一个 Tab

- 素材库页已经只允许一层 Tab（用户输入库 / 生成素材库）；再造一层就是重蹈 2.1.8 的覆辙。
- 「成片」不是一种**类别**（类别是 文案/图片/视频/音频），而是一种**来源**，混进类别行会把两个维度搅在一起。
- 所以：生成库里多一个「来源」下拉，类别行保持纯净。

## 二、改了什么

### 后端（素材列表新增标签精确过滤）

| 文件 | 改动 |
|------|------|
| `modules/media-assets/library-kind.ts` | 新增 `tagContainsSql()`：`JSON_VALID(COALESCE(tags, JSON_ARRAY())) AND JSON_CONTAINS(COALESCE(tags, JSON_ARRAY()), :tag)` |
| `modules/media-assets/dto/media-asset.dto.ts` | 查询 DTO 新增 `tag`（`@IsString @MaxLength(32)`） |
| `modules/media-assets/services/media-asset.service.ts` | 用 `Raw(tagContainsSql)` 接线到 `list()` |
| `modules/media-assets/TWO-LIBRARY.md` | 补接入说明（读生成库新增一行） |

**为什么口播成片要用标签而不是 source_type**：口播工坊产物与媒体生成任务的 `source_type` 同为 `media_job`，
区分不出来；口播工坊导入时打的标签是 `口播工坊`（`oral-workshop.service.ts` `importJobMaterials`），
标签才是唯一可靠标记。`JSON_VALID` 兜底历史脏数据（`tags` 非合法 JSON 时判不匹配，而不是让整页 500）。

### 桌面端（生成库「来源」筛选）

| 文件 | 改动 |
|------|------|
| `pages/Assets/library-tabs.ts` | 新增 `OUTPUT_SOURCES` + `outputSourceQuery()`（映射唯一口径）；`AssetLibraryQuery` 补 `sourceType/tag` |
| `api/media-asset-api.ts` | 列表查询参数补 `tag` |
| `pages/Assets/AssetLibrary.tsx` | 生成库显示「来源」下拉；`load()` 带上来源；切库复位；详情「来源」补全 agent/flow |

来源映射（`outputSourceQuery`）：

| 选项 | 查询参数 |
|------|----------|
| 全部来源 | （不带） |
| 口播成片 | `tag=口播工坊` |
| 官署产出 | `sourceType=agent` |
| 媒体生成 | `sourceType=media_job` |
| 任务输出 | `sourceType=task` |

> 「口播成片」**不叠加** `sourceType`：历史数据里 `manual + 标签` 的成片也要筛得到。

## 五、手工验收（真机）

1. 素材库 → 生成素材库：类别行下方出现「来源」下拉，输入库里**没有**这个下拉。
2. 选「口播成片」→ 只剩口播工坊导入的成片/封面/人声轨；选「官署产出」→ 只剩三省六部产出。
3. 切回「用户输入库」再切回生成库：来源自动复位成「全部来源」。
4. 不选来源时列表条数与上一版一致（没有误筛）。
5. 素材详情「来源」：官署产出显示「官署产出」（此前会显示成「手动登记」）。
6. 回归：两库切换、语义检索、上传素材、画中画待用队列、口播工坊取素材。
